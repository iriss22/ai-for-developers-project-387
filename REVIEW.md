# Критерии автоматического ревью PR

Единый источник критериев для авторевью: их использует workflow
[`.github/workflows/opencode-review.yml`](.github/workflows/opencode-review.yml),
чтобы оценка каждого PR была одинаковой и воспроизводимой.

## 1. Соответствие задаче

- PR закрывает ровно одну задачу из трекера; номер тикета указан в сообщении коммита.
- Нет изменений вне рамок задачи: дифф минимален, «заезжих» правок нет.
- Поведение приложения соответствует спецификации (`docs/specification.md`) и ADR из `docs/adr/`.

## 2. Качество кода

- Соблюдены правила из `AGENTS.md`: структура, стиль, именование.
- Сгенерированный код (SDK фронтенда, серверные интерфейсы из OpenAPI) не правился руками — изменения внесены в `contract/main.tsp` и перегенерированы.
- Нет закомментированного кода, отладочных выводов и `TODO` без тикета.
- Линтеры и форматирование проходят (`mise run check`), новые правила не отключены; узкие исключения согласованы и задокументированы.

## 3. Тесты

- Новое или изменённое поведение покрыто тестами (бэкенд — JUnit/MockMvc, фронтенд — Vitest/RTL).
- Тесты проверяют поведение, а не детали реализации; падающие и пограничные случаи учтены.
- Тесты запускаются и проходят локально и в CI.

## 4. Безопасность и риски

- Нет секретов, токенов и персональных данных в коде и истории коммитов.
- Не ослаблены права доступа, валидация и проверки в workflow и API.
- Оценён риск изменения: что сломается при выкатке и как это заметить.
- Заполненные разделы шаблона PR: проверки, риск и способ отката.

## Итог ревью

Каждый критерий получает вердикт «ок» или «замечание» с ссылкой на файл и строку.
Итог: `approve` (замечаний нет или только косметика) или `changes requested`
(есть замечания по разделам 1–4). Косметика не блокирует мердж.
